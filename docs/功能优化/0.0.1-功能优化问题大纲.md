# AI Employee 0.0.1 功能优化问题大纲

## 1. 本版本目标

本版本只做后台管理侧的基础数据查看和用户反馈入口，不扩展复杂的桌面工作台、模型配置引导、个人中心或运营分析系统。

后台管理员需要能够：

1. 查看哪些用户登录过系统。
2. 查看用户进入或使用过哪些智能体。
3. 查看每个用户登录次数、最近登录时间和智能体使用次数。
4. 通过后台菜单进入“用户反馈”，查看用户提交的反馈。
5. 复用现有 `/message-board` 能力，反馈类型默认使用“产品建议”。

## 2. 当前可复用能力

- 后端项目：`/Volumes/work_mac_1_5T/work/test`。
- 后端已有用户、管理员和登录相关数据结构。
- 后端已有 `message-board` 用户留言接口和 `/api/admin/message-board/*` 管理接口。
- 前端已有后台菜单权限系统和 `MessageBoardPage.vue` 管理页面。
- 后台路由中已经存在 `/admin/user-feedback` 和 `/admin/message-board` 相关入口，应优先确认现有实现并复用，不重复创建反馈系统。
- 现有留言分类中已有“产品建议”分类，新增用户反馈时默认使用该分类。

## 3. 功能一：后台查看用户登录情况

### 3.1 需求

在后台增加或完善用户登录统计列表，管理员可以查看：

- 用户昵称。
- 用户名或账号。
- 首次登录时间。
- 最近登录时间。
- 登录次数。
- 账号状态。

### 3.2 统计口径

- 每次用户成功登录，登录次数加 1。
- 登录失败不计入成功登录次数；如现有系统已有失败日志，可暂不纳入本版本页面。
- 同一用户从不同设备登录，仍按该用户账号累计。
- 页面打开、刷新或访问智能体页面不应重复增加登录次数。

## 4. 功能二：后台查看智能体使用用户

### 4.1 需求

管理员可以查看哪些用户使用过智能体，以及每个用户的使用次数。

列表至少展示：

- 用户昵称。
- 用户账号。
- 使用过的智能体名称。
- 首次使用时间。
- 最近使用时间。
- 使用次数。
- 最近一次使用状态。

### 4.2 统计口径

本版本将“使用过智能体”定义为：用户成功进入智能体并触发一次实际使用行为。仅登录、打开智能体详情页或浏览页面，不计入智能体使用次数。

如果当前系统还不能区分“打开”和“实际使用”，第一阶段可先按智能体运行接口被成功调用统计，并在页面中明确标注统计口径。

## 5. 功能三：后台用户反馈菜单

### 5.1 菜单

在后台侧边栏增加或确认已有菜单：

```text
用户反馈
```

建议路径：

```text
/admin/user-feedback
```

菜单使用现有权限系统控制，仅向有反馈查看权限的管理员展示。

### 5.2 数据来源

不新建反馈表，复用现有 `message-board`：

- 用户提交反馈使用现有 `/message-board` 能力。
- 后台列表优先使用现有 `/api/admin/message-board/posts` 接口。
- 反馈详情、状态处理、删除等能力复用现有留言板管理接口。
- 用户反馈默认分类为“产品建议”。
- 后台菜单名称显示为“用户反馈”，不再要求管理员理解“留言板管理”的内部实现名称。

### 5.3 后台查看内容

用户反馈列表至少展示：

- 提交用户。
- 反馈标题。
- 反馈内容摘要。
- 类型，默认显示“产品建议”。
- 提交时间。
- 处理状态。
- 详情、隐藏/显示、删除等现有操作。

本版本暂不要求新增复杂的工单流转、自动分派、优先级、SLA 或统计大屏。

## 6. 最小后端改造范围

### 6.1 登录统计

确认现有登录成功处理逻辑：

- 若已有登录日志表，直接增加按用户聚合查询接口。
- 若只有最近登录时间，没有登录次数，则新增最小登录记录或计数方案。
- 不修改已有 SSO 业务逻辑，优先在成功登录完成处补充统计。

### 6.2 智能体使用统计

新增最小使用记录，建议字段：

```text
id
user_id
agent_id
agent_name
action_type
status
created_at
```

管理员查询时按 `user_id + agent_id` 聚合，返回首次使用、最近使用和使用次数。

不记录 API Key、完整提示词和完整模型返回内容。

### 6.3 用户反馈

优先复用现有表和接口：

- `message_board_posts`
- `message_board_categories`
- `/api/admin/message-board/posts`
- `/api/admin/message-board/categories`

只有现有 `message-board` 无法保存反馈来源或智能体关联时，才补充可选字段；不重复建设一套 `user_feedback` 表。

## 7. 前端改造范围

后端项目 `/Volumes/work_mac_1_5T/work/test`：

- 确认 `AdminLayout.vue` 的后台菜单显示“用户反馈”。
- 复用或调整 `UserFeedbackPage.vue` / `MessageBoardPage.vue`。
- 增加用户登录统计页面或在用户列表中增加登录次数列。
- 增加智能体使用用户查询页面，支持按智能体和用户筛选。

桌面项目 `web-admin/frontend` 本版本只需在用户反馈提交入口中将默认分类设为“产品建议”；不调整整体桌面壳层架构。

## 8. 0.0.1 实施顺序

1. 确认现有“用户反馈”菜单和 `/admin/user-feedback` 路由是否已可用。
2. 确认 `/message-board` 的默认分类为“产品建议”。
3. 补充后台用户登录次数和最近登录查询。
4. 补充智能体使用记录和按用户聚合查询。
5. 在后台页面展示登录统计、智能体使用统计和用户反馈。
6. 使用管理员权限、普通用户权限分别验证数据可见范围。

## 9. 验收标准

- 后台菜单中可以看到“用户反馈”。
- 点击“用户反馈”可以进入已有 `message-board` 数据管理页面。
- 新提交反馈默认分类为“产品建议”。
- 管理员可以查看登录过的用户、登录次数和最近登录时间。
- 管理员可以查看使用过智能体的用户、使用次数和最近使用时间。
- 登录统计和智能体使用统计不会因刷新页面重复累计。
- 无权限用户不能访问后台统计接口和用户反馈管理接口。
- 不新增重复的反馈数据表，不破坏现有留言板功能。

## 10. 本版本明确不做

- 不做复杂桌面端全局导航重构。
- 不做模型供应商首次配置向导。
- 不做个人中心从 AI 对话中抽离的完整改造。
- 不做 Token 计费、费用统计和 BI 大屏。
- 不做复杂反馈工单流转。
