# AI Employee 0.0.1 功能优化方案

## 1. 方案结论

本版本采用“Windows 风格桌面工作台 + 全局账户菜单 + 首次配置引导 + 服务端使用事件”的组合方案：

1. 保留现有桌面窗口壳层，不把产品改成网页后台式侧边栏。
2. 在桌面壳层的固定区域增加当前用户入口，个人中心不再依赖 AI 对话窗口。
3. 将模型供应商配置作为独立桌面应用，同时在首次使用 AI 前提供明确引导。
4. 在 Agent 实际执行成功或失败时由后端记录使用事件，提供管理员查询接口和前端使用记录窗口。
5. 先完成可发现性、配置闭环和最小统计，不在 0.0.1 引入复杂运营报表。

## 2. Windows 风格桌面 UI 设计

### 2.1 桌面层级

```text
桌面背景
├── 桌面快捷方式：AI 对话 / 工作台 / Agent / 模型供应商 / 个人中心
├── 底部任务栏 Dock：固定常用应用、当前打开窗口
└── 系统区域：当前用户头像、配置状态、通知、退出登录
```

桌面壳层继续由 `DesktopSystemShell.vue` 负责窗口、任务栏和启动器。个人中心、模型供应商和 Agent 使用记录作为独立窗口打开，不在 AI 对话页面内部嵌套完成主要设置。

### 2.2 全局账户入口

在桌面壳层右上角或系统区域增加：

```text
头像  用户名 ▾   模型：未配置/正常/异常
```

点击后显示 Windows 风格账户菜单：

- 个人中心
- 模型供应商
- Agent 使用记录（管理员或有权限用户可见）
- 关于 AI Employee
- 退出登录

菜单必须在工作台、AI 对话、任务、项目等所有窗口状态下可用。窗口最小化、最大化、切换窗口不应影响入口显示。

### 2.3 工作台快捷入口

现有工作台继续作为登录后的默认桌面，不强制用户先进入 AI 对话。工作台增加四个状态卡片：

- 当前账户：显示用户名、角色和最近登录时间。
- 模型配置：显示“未配置/已配置/测试失败”，提供“立即配置”。
- 最近 Agent：显示最近实际运行的 Agent。
- 待处理事项：显示模型测试失败、权限不足或任务失败等需要用户处理的事项。

## 3. 模型供应商配置设计

### 3.1 状态模型

前端不要只展示“禁用”。统一使用以下状态：

| 状态 | 用户看到的文案 | 可执行动作 |
| --- | --- | --- |
| 未配置 | 尚未配置模型供应商 | 去配置 |
| 已配置未启用 | 配置已保存，尚未启用 | 启用并测试 |
| 已启用 | 可正常使用 | 测试连接 / 编辑 |
| 测试失败 | 连接失败：查看原因 | 重试 / 修改配置 |
| 无权限 | 当前账号无权使用 | 查看权限说明 |
| 系统不可用 | 服务暂不可用 | 查看服务状态 |

任何不可操作状态都要给出原因；任何可操作状态都必须显示按钮或明确的窗口入口。

### 3.2 首次使用流程

用户登录后进入工作台。若没有可用模型供应商，工作台显示一次轻量引导：

```text
还没有可用的模型供应商
配置模型后才能开始 AI 对话
[立即配置] [稍后处理]
```

用户点击 AI 对话且模型不可用时，不打开空白页面，而是在对话窗口中显示配置引导面板。引导支持“稍后处理”，但必须保留顶部状态提示。

### 3.3 配置表单

首期字段：

- 供应商名称/类型。
- API Key，默认掩码显示。
- Base URL，可选并显示示例。
- 默认模型。
- 是否启用。
- 保存配置。
- 测试连接。

保存和测试分为两个动作：保存只校验字段格式，测试连接才验证供应商可用性。测试过程显示加载状态，成功或失败都使用明确的 Toast/表单错误和可理解的修复建议。

### 3.4 配置来源说明

在表单顶部显示当前配置来源：

- 个人配置：仅当前用户使用。
- 共享配置：由其他授权用户或管理员共享。
- 系统默认：由平台统一提供。

默认模型选择只展示当前用户有权限使用且处于启用状态的供应商和模型。

## 4. 个人中心设计

### 4.1 页面定位

新增独立桌面应用“个人中心”，建议路由为 `/account` 或 `/settings/account`，不再要求用户进入 `/ai/chat` 才能访问。

### 4.2 页面布局

采用 Windows 设置窗口风格：

```text
个人中心窗口
├── 左侧账户导航
│   ├── 账户概览
│   ├── 模型供应商
│   ├── Agent 使用记录
│   └── 安全与登录
└── 右侧内容区
```

首期内容：

- 账户概览：头像、用户名、昵称、角色、邮箱和最近登录信息。
- 模型供应商：跳转或打开模型配置窗口。
- Agent 使用记录：普通用户查看自己的记录；管理员按权限查看统计。
- 安全与登录：退出登录，后续预留密码、设备和会话管理。

### 4.3 账户菜单与页面的关系

账户菜单是全局快捷入口，个人中心是完整管理页面。两者不能互相替代：菜单负责快速到达，页面负责承载完整信息。

## 5. Agent 使用记录设计

### 5.1 统计口径

“使用过”定义为：服务端收到 Agent 执行请求，并产生开始事件；推荐同时记录完成、失败和取消事件。仅打开 Agent 页面、创建草稿或获得权限不计入实际使用。

### 5.2 D1 数据模型建议

在后端新增迁移文件，例如 `db/0089_agent_usage_events.sql`，不要直接改写已执行的历史迁移。最小字段建议：

```text
id                  TEXT PRIMARY KEY
user_id             TEXT NOT NULL
agent_id            TEXT NOT NULL
project_id          TEXT
conversation_id     TEXT
execution_id        TEXT NOT NULL
event_type          TEXT NOT NULL  -- started/completed/failed/cancelled
status              TEXT NOT NULL
model_vendor_id     TEXT
model_name          TEXT
input_tokens        INTEGER
output_tokens       INTEGER
duration_ms         INTEGER
error_code          TEXT
created_at          TEXT NOT NULL
```

建议索引：

- `(agent_id, created_at)`：按 Agent 查询使用者。
- `(user_id, created_at)`：查询当前用户记录。
- `(user_id, agent_id, created_at)`：查询用户与 Agent 的组合使用情况。
- `(execution_id, event_type)`：避免事件重复写入。

API Key、完整提示词和模型返回正文不进入该表。

### 5.3 后端接口建议

接口命名可按现有 Worker 路由规范落地：

- `GET /api/agent-usage/me`：当前用户自己的使用记录。
- `GET /api/admin/agents/:agentId/users`：管理员查询某 Agent 的使用用户。
- `GET /api/admin/agent-usage/summary`：管理员查看 Agent、用户、时间范围汇总。
- `POST /api/agent-usage/events`：仅供受信任的 Agent 执行链路写入，不允许客户端任意伪造统计。

更推荐由 Agent 执行接口内部写事件，而不是让浏览器直接上报。若必须由前端上报，后端应以服务端生成的 `execution_id` 和已授权 Agent 为准进行校验。

### 5.4 管理员页面

新增独立窗口“Agent 使用记录”：

- 顶部：时间范围、Agent、用户、状态筛选。
- 主表：用户、Agent、首次使用、最近使用、执行次数、失败次数、最近模型。
- 详情：展开查看执行 ID、项目、会话、耗时和错误码。
- 空状态：明确显示“暂无实际执行记录”，不要显示为加载失败。

## 6. 前端改造边界

建议涉及以下现有文件或模块：

- `web-admin/frontend/src/components/DesktopSystemShell.vue`：增加全局账户菜单和模型状态指示。
- `web-admin/frontend/src/utils/desktop-shell.js`：注册个人中心、使用记录等桌面应用及默认快捷入口。
- `web-admin/frontend/src/router/index.js`：增加独立账户、模型配置和使用记录窗口路由。
- `web-admin/frontend/src/views/desktop/DesktopWorkbench.vue`：增加账户与模型状态卡片。
- `web-admin/frontend/src/views/llm/ModelProviderManager.vue`：补足状态文案、配置入口、测试连接和失败反馈。
- `web-admin/frontend/src/views/users/UserSettings.vue`：作为个人中心账户概览或账户设置子页面复用。
- 新增 `web-admin/frontend/src/views/account/AccountCenter.vue`：承载个人中心主窗口。
- 新增 `web-admin/frontend/src/views/employees/AgentUsage.vue`：承载用户/Agent 使用记录。

具体文件是否拆分，以现有组件复用能力和权限路由实现为准，不在 0.0.1 为追求命名一次性大范围重构。

## 7. 后端改造边界

后端项目 `/Volumes/work_mac_1_5T/work/test` 当前已有 `users`、`admin_users`、`model_vendors`、`vendor_models` 和 `provider_assignments` 等基础结构。0.0.1 重点补充：

1. Agent 使用事件迁移和索引。
2. 当前用户与管理员权限下的查询接口。
3. Agent 执行链路中的事件写入。
4. 模型供应商配置的状态查询、保存和连接测试接口（优先复用已有接口，不重复造表）。
5. 用户基本信息与会话状态接口，供桌面壳层显示账户菜单。

后端实现必须沿用现有 Worker/CORS/鉴权方式，并明确管理员权限校验。不能因为前端需要显示用户菜单而把用户密码、API Key 或内部角色数据直接返回给客户端。

## 8. 跨平台要求

### Windows

- 使用窗口标题栏、最小化、最大化、关闭和任务栏切换的桌面心智。
- 快捷入口使用通用图标和文字，不依赖 macOS 菜单栏。
- 支持 Windows 常用缩放比例，避免固定像素导致表格和配置表单溢出。

### macOS

- 保留同一套信息架构和账户入口。
- 不依赖仅 Windows 存在的路径、注册表或快捷键。
- 窗口关闭、最小化和返回行为适配 macOS 容器，但不改变业务路由。
- 安全、公证和安装问题属于发布流程，和本功能优化解耦。

### 共用原则

- 路由、权限、接口和数据口径完全一致。
- 本地窗口状态可以分别适配，但账户和模型配置不能只存在本地。
- 断网时显示明确的离线状态，不把网络失败伪装成“禁用”。

## 9. 0.0.1 实施顺序

1. 先做全局账户入口和独立个人中心，解决用户找不到账户的问题。
2. 再做模型状态统一、配置引导和连接测试，解决用户无法开始使用的问题。
3. 同步增加 Agent 使用事件表和服务端写入点。
4. 最后接入 Agent 使用记录页面和管理员筛选查询。
5. 通过 Windows 与 macOS 的窗口、缩放、路由和权限验收后发布。

## 10. 验收标准

- 登录后不打开 AI 对话，也能从桌面全局区域进入个人中心。
- 工作台能明确显示模型配置状态，点击后一定有窗口、提示或错误反馈。
- 新用户可以从引导完成供应商配置、保存和连接测试。
- Agent 执行成功、失败、取消均能产生可追踪的服务端事件。
- 管理员可以按 Agent 查询实际使用过的用户；普通用户只能查看自己的记录。
- 使用记录不包含 API Key、完整提示词和完整模型返回内容。
- Windows 和 macOS 使用同一套业务入口，窗口行为适配各自容器。
- 前端类型检查、构建和后端相关测试通过；接口鉴权失败时返回明确错误。

## 11. 暂不纳入 0.0.1

- 复杂 BI 看板和实时大屏。
- 按 Token 计费、充值和账单结算。
- 多组织复杂数据隔离重构。
- 自动探测所有第三方供应商的模型清单。
- macOS 公证、Windows 代码签名等发布工程问题。
