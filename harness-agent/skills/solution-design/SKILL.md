# 技术方案设计技能

## 目标

把需求转化为可实现、可验证、可演进的技术方案，避免过早编码和无边界架构。

## 方案结构

1. 背景与问题边界。
2. 当前实现与事实证据。
3. 目标、非目标和验收标准。
4. 推荐方案与关键取舍。
5. 模块、接口、数据流和状态变化。
6. 文件变更清单与实施顺序。
7. 测试、观测、发布、回滚和兼容策略。
8. 备选方案及不采用原因。

## 设计原则

- 优先复用当前技术栈、组件和基础设施。
- 默认向后兼容；破坏性变化必须显式标记。
- 将领域逻辑、适配层、展示层和基础设施边界说清楚。
- 对失败、取消、重试、超时、幂等和并发进行设计。
- 对 macOS / Windows 的路径、进程、权限、打包和配置差异给出方案。
- 方案要能拆成小步提交，不要求一次性重构整个项目。
